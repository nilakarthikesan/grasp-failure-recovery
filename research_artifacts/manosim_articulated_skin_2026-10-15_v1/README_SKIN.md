# Source-complete articulated MANO skin qualification

This separately frozen development study implements all135 pose-corrective terms and16-bone linear blend skinning for the exact saved HUG shape. It evaluates the fixed109-state grid on original cases20 and28, with no new HUG inference, task labels, object queries, controller tuning, training or physics integration. The original saved pose, shape, face topology and scientific acceptance thresholds remain unchanged.

`skin_kinematics.py` is a pure explicit-buffer Torch implementation. `skin_case.py` loads the pinned independent manotorch implementation only inside the frozen run. Every state compares candidate float32 skin to source float32 matrix-input skin; one additional original axis-angle source evaluation compares to the unchanged saved native target. Explicit float64 casts of literal source buffers provide a continuous derivative profile. The float64 skin is compared descriptively/numerically to source float32; it does not replace the frozen native surface.

The source32 named-state q0 and continuous64 q0 are each explicitly checked against the unchanged saved native surface using the inherited5micrometer numerical comparison. This joins the independent original axis-angle source reconstruction to the separately assembled named simulator state. A displaced baseline cannot pass merely by agreeing with another implementation at the same wrong pose.

The grid contains q0,90 individual finger-axis perturbations at±2degrees, six fixed coupled perturbations (±0.5,±2,±5degrees), six wrist-axis perturbations at±2degrees, and six world-slide perturbations at±2mm. This finite development grid does not certify a continuous motion envelope. Each input remains independently identifiable and all109 source/candidate vertex arrays are retained for saved-only rendering.

The actual original generated XML is compiled once per case to verify67 qpos,51 DOFs,51 actuators and19 named joints, their type/address/body/tree metadata, rest body quaternions and literal world-slide axes.109 `mj_integratePos` calls compare the engine's local ball right increment to independently composed Hamilton quaternions. Original qpos is never overwritten. There is no MjData, engine forward/FK or contact calculation in this study. A successful tangent-integration comparison proves this state convention only; simulator geometric finger motion and physical contact remain NOT_RUN.

At q0, all51 continuous64 tangent columns are computed by separate forward-AD evaluations, compared with102 central-difference evaluations (step1e-6), and checked with one force VJP for virtual work. Numerical derivative comparisons are absolute1e-8 plus relative1e-6; virtual-work comparisons are absolute1e-10 plus relative1e-10. The inherited5micrometer source reconstruction comparison is numerical and is never a contact/surface allowance. The same applies to the1e-12 quaternion integration comparison. Source skin parity is an independent implementation comparison; FD/VJP qualify the candidate derivative, rather than independent physical truth.

Per-case operation caps are one model compilation, one source layer construction, one original source axis-angle evaluation,109 source matrix skins,109 candidate float32 skins,109 candidate float64 skins,51 forward-AD skins,102 FD skins, one VJP,109 quaternion integrations,600seconds, zero MjData/engine forwards/physics. Torch intra-op threads are fixed to1; inter-op count is reported without silently changing process-global policy. Every counted operation is announced before work; every NPZ has a creation-time SHA/size receipt immediately after writing. Raw arrays belong in the ignored run root selected by the runner.

`declaration()` performs only metadata/path/library import reads. `run_case(spec, output_dir, protocol, checkpoint_callback)` is the only native operation entry point. The root-owned `run_skin.py` prepares/freeze-checks/executes the bounded children. Contact-law source and synthetic qualification live separately in `contact_law.py`; this skin study does not apply that law or claim contact dynamics are qualified. All admission fields remain false and physical outcome remains null.

Manufactured controls use synthetic buffers and metadata only. The early arbitrary2e-17 neutral-algebra assertion failed at2.7755575615628914e-17.
