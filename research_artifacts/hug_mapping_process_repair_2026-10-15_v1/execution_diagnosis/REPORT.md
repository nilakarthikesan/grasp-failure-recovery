# HUG execution-path diagnosis

Read-only source trace, 15 October 2026. No production edits, geometry queries, FK, native generation, optimization or eval execution. The numerical fit agent owns the separate gradient/repeatability experiment; this report does not claim its results.

The most actionable defect is in the active Dex `VectorOptimizer`: its returned scalar is the averaged SmoothL1 vector-distance loss, but the supplied gradient additionally contains `2 * norm_delta * (x - last_qpos)`. The matching quadratic term is absent from the scalar. With the configured default `normal_delta=0.004`, these are inconsistent away from the previous iterate. This is a real numerical-contract defect in the inspected dependency, not proof that its correction will preserve every surface or that it caused all previous failures. The same dependency catches an optimizer `RuntimeError` and returns the previous pose after printing the error; our wrapper does not expose a structured solver status.

The larger modeling limitation is also explicit in code: the production mapper receives native hand landmarks, constructs ten wrist-to-tip/middle vectors, and fits Shadow palm-to-tip/middle vectors. Neither the object mesh nor the native skin enters that objective. It overrides the teleoperation scale to 1.0 and disables output filtering, then calls the stateful solver twenty times. The fixed global correspondence puts the Shadow palm origin at the MANO wrist. Correct coordinate composition verifies that implemented convention; it does not establish that the palm and finger surfaces occupy equivalent regions around the object. Fixing units, axes or joint order again is not the evidence-supported explanation for the current six cases.

The source/target path is:

1. Decode saved camera-frame MANO landmarks and wrist transform.
2. Invert the wrist transform and rotate into the Dex operator convention.
3. Fit ten local vectors; clamp optimizer output to physical joint limits.
4. Validate landmark vectors relative to the Shadow palm; the 10 mm gate concerns the average of five tips.
5. Compose camera-to-world and native-wrist-to-operator rotations, including the solved wrist joints. Select the native wrist position as the target Shadow palm position; compensate the floating forearm root using FK.
6. Execute the controller's approach and closure. In `fixed_grasp_lift_v2`, the nominal mapped pose is reached at the closure command endpoint, then fixed +0.2 rad flexion offsets (clipped at limits) are introduced during settling and retained for lift/hold. Actual servo state can differ from both commands.
7. Score the executed trajectory. This label belongs to that mapped-plus-controller attempt, not to the unmodified native MANO grasp or the nominal pose alone.

The saved collection records nominal, requested-noise, commanded and measured states separately, along with source-file hashes and the execution protocol. The current static audits address the nominal pre-force-close target. They do not certify the later force-close geometry or actual tracking. Fixed closure is a declared controller choice, not by itself a mapping bug; attribution must preserve that distinction.

Two integrity fixes should accompany a versioned mapper, although they do not explain the audited six-case surface failures:

- The older `grasp-eval` case path bypasses its mean-tip gate in saved-proposal mode, and substitutes a table-parallel palm placement when the world-camera transform is missing. These are intentional debug escape hatches, yet ordinary completed result output does not explicitly mark the lost mapping-fidelity scope. Scientific execution should require the camera binding and gate independently of whether inference is fresh; any debug replay should have an explicit mode/status. The 32-case collection path already requires the camera transform, checks rigidness and applies the mean gate, so the existing nine FAILs cannot be blamed on this fallback.
- The MANO translation wrapper checks the installed YAML hash, while effective behavior also depends on the optimizer implementation, scale/filter overrides, repeated-solve policy, initialization and failure handling. Generic results record a Git commit and package version; those cannot alone identify dirty source or a patched dependency. The noisy collector does additionally hash project sources, but its list does not bind the Dex optimizer source/config. A new policy should record the complete effective mapper manifest rather than reuse the old strategy ID for changed behavior.

A bounded next implementation can be a new, explicitly selected static-solver variant; the production default and historical artifacts should remain unchanged. First make the scalar and Jacobian describe exactly the same declared objective, choose and record whether a static quadratic prior is present, reset per-input solver state, and surface failure/termination rather than silently treating the previous iterate as convergence. Test callback derivatives and order independence before testing the same saved grasps. A corrected hand-only solve is a baseline, not an object-aware solution. Any subsequent object-relative fit must receive the actual object reference and explicit native/robot anatomical correspondence, preserve the original safeguards, and use a frozen finite solve budget. A better objective is a proposed remedy; fidelity still has to be measured on the resulting poses.

No claim of global infeasibility is supported by the previous local/refused fits. No new pass threshold or retrospective reclassification is proposed. The immediate distinction is: numerical objective consistency can be fixed; object-aware surface preservation must be optimized and independently assessed; dynamic predictive adequacy remains a later study.
