# Pinned compiler inertia representation check

This is a source-backed software validation correction after the capsule v1 preflight refused its first compiled model. V1 stopped at one model and zero data constructions, forwards or steps. Its compiled inertia operands were not saved, so this note does not diagnose an observed inertia tensor discrepancy or assert that the failed model was physically correct. The original v1 source/protocol/report and independent failure receipt remain unchanged. No native model, FK, geometry, contact or physics operation was used to derive or test this correction.

The primary source is the official MuJoCo3.4.0 [`src/user/user_util.cc`](https://github.com/google-deepmind/mujoco/blob/3.4.0/src/user/user_util.cc#L611-L755), copied here byte-exact with SHA256 `f9d5ef77317707039f12658e620ff3393f1eb8a0e7087111e4740207f2ee2522`. `mjuu_fullInertia` constructs the symmetric tensor and calls compiler utility `mjuu_eig3`. This is distinct from a claim about an engine utility called `mju_eig3`. [`mjCBody::Compile`](https://github.com/google-deepmind/mujoco/blob/3.4.0/src/user/user_objects.cc#L2203-L2209) uses that full-inertia conversion.

The Jacobi implementation has at most500 iterations and `kEigEPS=1e-12`. At each iteration it forms `D=Rᵀ I R`, returns the diagonal entries as principal inertias, and stops either when the largest off-diagonal magnitude is below the absolute1e-12 threshold or when the proposed rotation cosine exceeds `1−1e-12`. It may therefore leave a small off-diagonal residual much larger than128 machine epsilons times the tensor magnitude. The previous whole-tensor machine-equality guard was unsupported by this algorithm.

For the second stopping condition, write the selected2×2 block as `[a,b;b,d]`, `Δ=d−a`, and `t=tan(θ)` for its proposed Jacobi rotation. The exact Schur relation is `|b|=|Δ|·|t|/(1−t²)`, and `c=1/sqrt(1+t²)`. Thus `c>1−k` implies `t²<(1−k)⁻²−1`; its small-angle coefficient is approximately1.4142e-6 times the selected diagonal gap. Using the full diagonal span is a conservative bound over any selected pair and remains invariant to the compiler's final axis permutation.

The new pure-array helper `inertia_representation_receipt` uses the actual compiled quaternion and principal values. It checks the diagonal of `Rᵀ I_XML R` against those values at arithmetic precision and checks the largest off-diagonal against both source stopping branches. Source inertia and physical qualification limits are never changed. The receipt separately reports the full tensor reconstruction error; a nonzero value is not erased.

For finite normal IEEE float64 arithmetic with correctly rounded square root, `u=eps/2` and `γₙ=nu/(1−nu)` give the explicit arithmetic envelopes. `γ32` conservatively covers the fewer-than32 rounded operations in the selected2×2 Schur/cosine branch. The cosine lower envelope is `(1−k)/(1+γ32)`; square/inverse/subtraction/root/coefficient are rounded outwards with `nextafter`. A further `(1+γ32)` factor covers the relation between the rounded Schur variable and the selected block. `γ128·||I_XML||∞` covers quaternion normalization/rotation and the small matrix products used in the diagonal/off-diagonal readback comparison. This allowance concerns the numerical representation of one fixed source tensor; it is not a material, pose, contact or trajectory tolerance.

The source does not export the actual compiler iteration count, and its caller does not reject the500-iteration return itself. The validator therefore records that count as unknown, does not infer convergence from model compilation, and independently refuses an output eigenframe whose residual fails the declared postconditions. It does not claim to reproduce the compiler's exact iteration path or count.

Manufactured controls cover exact rotated tensors; nonzero residuals satisfying each pinned stopping branch that the old machine-equality rule would wrongly reject; diagonal mutation including the existing10% wrong-inertia control; and an off-diagonal residual outside the derived envelope. The first raw pytest invocation lacked the existing dependency bootstrap and failed during import before tests ran. The supported static wrapper then passed all44 manufactured controls with zero integration calls (`/private/tmp/manosim_capsule_inertia_controls_attempt1.json`). No actual failed-model inertia array was evaluated by those controls.

The prospective v2 harness must save its already-compiled arrays before this check, then retain per-body numerical receipts in command-contract metadata. That is the next measured test; this note supplies no new model or physics result and grants no collection/training admission.
