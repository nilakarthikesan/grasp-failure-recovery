# Running the project

## Install

Requires Python 3.10 or later. Initialize the pinned Shadow model submodule
and install the evaluation tools:

```bash
git submodule update --init --recursive
python3 -m venv .venv
source .venv/bin/activate
pip install -e '.[dev,eval,prediction]'
```

The `dex-urdf` submodule supplies the Shadow Hand model. HUG source, its
checkpoint and licensed MANO assets must be provisioned separately for fresh
inference. See [the observation contract](HUG_OBSERVATION_PREFLIGHT.md) and
[multi-scene guide](MULTI_SCENE_COLLECTION.md) for paths and provenance.

On macOS, offscreen simulation commands use `MUJOCO_GL=cgl`.
Native MuJoCo viewing uses `mjpython` with `MUJOCO_GL=glfw`.
The `inspect-adroit` command reports the stock environment's observation,
actuator and contact layout.

## Unified provider experiments

Reinstall the editable package after pulling entry-point changes. The
[experiment guide](GRASP_EVAL_CLI.md) defines requests, sample selections,
physical cases and resumable output bundles.

```bash
grasp-eval validate /path/to/experiment.yaml
grasp-eval run /path/to/experiment.yaml
grasp-eval status /path/to/experiment.yaml
grasp-eval resume /path/to/experiment.yaml
grasp-eval view /path/to/experiment.yaml
```

HUG generation also takes `--hug-root` and `--checkpoint`. Official saved
DexGraspNet import is documented in [DEXGRASPNET_REPLAY.md](DEXGRASPNET_REPLAY.md).
These generic runs are execution records; compatible velocity/command recording
is still required before using them with the existing prediction exporter.

## Inspect and execute a HUG grasp

Inspect a prediction generated by a trusted HUG runtime:

```bash
inspect-hug-prediction /path/to/grasp_pred/example.pkl
view-retargeted-hand /path/to/grasp_pred/example.pkl
```

Prediction pickle files must come from a trusted source because loading a pickle
can execute code.

Run a case with captured observation inputs and a declared inference seed:

```bash
run-hug-eval-case \
  eval_cases/hug_case_001/case.yaml \
  --output runs/hug_case_001 \
  --hug-root ../hug \
  --checkpoint ../hug/checkpoints/hug_full.safetensors
```

To execute a trusted saved prediction referenced by the case manifest:

```bash
run-hug-eval-case \
  eval_cases/hug_case_001/case.yaml \
  --output runs/hug_case_001_saved \
  --no-inference
```

For live viewing on macOS, invoke the case runner with `mjpython` and `--viewer`.
The [manifest guide](EVALUATION_MANIFEST.md) defines required case fields,
environment/protocol IDs and outputs. The original v2 executor, corrected v3
checks and explicit v4 wrist diagnostic have separate provenance.

## Collect and inspect recordings

Collect a small batch from a declared saved-proposal manifest:

```bash
python -m grasp_failure_prediction.evaluation.noisy_rollouts cases.json \
  --project-root . --output runs/noisy_pilot \
  --noise-amplitudes 0 0.05 0.15 --repetitions 1 --seed 9000
```

See [the collector guide](NOISY_ROLLOUT_COLLECTION.md) for the manifest format,
logged noise fields and outcome definitions. Fresh scene captures and proposals
are covered by [the multi-scene guide](MULTI_SCENE_COLLECTION.md).

Review local result bundles and attached replays:

```bash
view-eval-results --runs-root runs
```

The viewer opens `http://127.0.0.1:8765/` on the machine running it.
Stop it with `Ctrl-C`. A repository clone contains the published derived
datasets and evidence bundles, not all raw rollouts or HUG runtime assets.

## Reproduce the baseline

```bash
python -m grasp_failure_prediction.prediction.model \
  research_artifacts/object_scene_pilot_v1 \
  --output runs/baseline_reproduction
```

Use a new output directory. The original dataset, split membership and model
bundle are described in [DATA_SPLITS.md](DATA_SPLITS.md) and
[PREDICTION_BASELINE.md](PREDICTION_BASELINE.md).

## Recorded noise demo

```bash
python3 -m http.server 8767 --bind 127.0.0.1 --directory docs/demos/grasp-noise
```

Open `http://127.0.0.1:8767/`. The [demo guide](demos/grasp-noise/README.md)
explains its historical recordings and provenance.

## Supporting Panda/ACT pipeline

The optional Panda package collects and trains a manipulation policy on a
weighted-container task. It is separate from the HUG/Shadow Hand outcome
experiments. Its earlier design is retained in
[the training specification](PART_I_TRAINING_SPEC.md).

For the recorded macOS ARM64 stack:

```bash
pip install -e '.[dev,robot]' -c constraints/part1-macos-arm64.txt
pip install 'lerobot[dataset]' -c constraints/part1-macos-arm64.txt
MUJOCO_GL=cgl validate-stack
MUJOCO_GL=cgl python scripts/run_part1_pipeline.py --workdir runs/part1_smoke
```

Individual stages are available as:

```bash
MUJOCO_GL=cgl collect-demos runs/demos.hdf5 --split train
MUJOCO_GL=cgl export-demos runs/demos.hdf5 runs/lerobot
MUJOCO_GL=cgl train-act runs/lerobot runs/policy
MUJOCO_GL=cgl eval-act runs/policy
```

The end-to-end smoke run checks integration; it does not establish a competent
learned policy or a HUG grasp outcome result.
