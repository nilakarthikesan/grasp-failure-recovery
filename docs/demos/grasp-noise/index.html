Recorded simulation experiment · 9 October 2026

See what noise changes

Noise is a deliberate change to a robot command. Here, we draw a bounded random angle offset for each finger joint, then keep that offset fixed while the hand closes, lifts and holds. Different offsets can make the same planned grasp succeed or fail.

These are saved results. Changing the controls selects an existing trial and recorded time. It does not run new physics or predict an untested outcome.

All five trials below use the same cube, HUG proposal and random noise direction. The strength scales that direction. The displayed bound is the maximum requested offset for any finger joint; each joint gets its own value.

3. Watch the recorded grasp

These two videos replay the saved simulator poses for the same HUG proposal. The noise affects 22 finger joints together; one joint in the diagram cannot explain the failure by itself.

Label 1 requires hand/object contact, at least 14 cm peak lift, two consecutive hold seconds at least 12 cm above the start, no more than 2 cm peak-to-final drop, no early hand/table collision and completion within 10 seconds. Label 0 means a completed attempt failed these checks. Runtime or validation errors receive no binary label. Final outcomes do not yet tell us when a failure became predictable.

Ten HUG proposals × five strengths, using one cube and one initial RGB-D observation; zero runtime or validation errors. The stronger offsets are stress tests, not calibrated hardware-error ranges. This tests the collection pipeline; it does not establish a general success rate or real-world reliability.

Do we need more elaborate noise?

We have met the initial bounded joint-noise requirement and saved a labeled pilot. More elaborate perturbations should answer a specific question. They are optional next experiments, not a prerequisite for understanding this result.

Implemented and recorded here

Fixed joint bias

A different bounded angle offset for each finger joint, drawn once per attempt. It tests whether a grasp survives imperfect finger commands.

Possible next experiment · not run here

Smooth, changing joint noise

A bounded offset that varies gradually during closing or holding. It would test sensitivity to small disturbances during motion. Its size and timing need calibration.

Different question · not run here

Dynamics variation

Change object friction, mass or controller properties between attempts. This tests sensitivity to physical assumptions, and requires careful contact-physics checks.

Different question · not run here

Observation noise

Perturb camera depth or measured robot states. This tests what the model sees, rather than directly changing the grasp command.

The full project is still in progress: varied objects, thousands of trajectories, appropriate observations, separate training/validation/test sets, a prediction model and real grasp-failure data remain to be developed.

Where the data is stored

This page embeds the actual recorded traces and two saved videos, so it needs no external service. The source paths identify the collection machine’s ignored runs/ files. The embedded demo works independently of those originals.

What each saved file contains
  • actions.npz: requested and applied noise, planned and commanded joint targets, simulator states.
  • trajectory.npz: timestamps, phases, measured hand and object motion, contact records.
  • result.json: final task outcome and evaluation metrics.
  • collection_metadata.json: binary label, noise settings and provenance.
  • scene.mjb: the compiled simulation scene used for replay.
